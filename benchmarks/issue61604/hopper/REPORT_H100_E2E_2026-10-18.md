# Issue #61604 H100 端到端验证阶段报告

日期：2026-10-18（UTC）  
结果目录：`results/issue61604/hopper/20261017T230937Z/`（本地忽略目录，原始数据未提交）  
测试状态：**主高压力同步场景完成 5 对确认；完整 H100 验证矩阵未完成。**

## 结论摘要

在 H100 上，当前 patch 在“16,384-token 共享前缀、128-token 唯一后缀、256-token 输出、32 并发、1130 KV blocks”的受控 KV 压力场景中，5 对同步确认的输出吞吐平均提高 **3.36%**，其中 4/5 对提高、1/5 对下降。配对均值的双侧 95% Student-t 区间为 **-0.57% 到 +7.29%**，包含零；因此目前只能说观察到小幅正向趋势，不能据此宣称稳定收益。

TTFT p99 与端到端 p99 的配对均值分别下降 3.19% 和 3.62%，但两者 95% 配对区间也跨零。流式 chunk 间隔 p99 平均反而增加 2.11%；且服务返回的流块常包含多个 token，所以该值不是 token 级 ITL，不能据此解释为 TPOT/ITL 变化。

本次运行中 base 与 patch 的 prompt token IDs、输出长度、成功状态和结束原因均逐请求一致。输出 token IDs 的精确一致率为 82.5%–96.0%；同 seed 的 base-base 控制为 92.0%。patch 的逐 token 差异率没有高于该次 base-base 控制，但这不能替代对差异来源的数值正确性调查，也不能单凭此结果证明 KV 生命周期完全正确。

**决策：**当前结果支持“该机制在特定持续 KV 压力下可能改善同步 serving”的假设，但证据尚不足以支持一般端到端收益或 PR 性能结论。默认异步、默认 KV 容量、短/无共享前缀、churn，以及代表性大模型均未完成；合并/推广结论应等待这些结果和正确性检查。

## 机制确认

独立诊断运行确认 patch 的 fast path 确实启用：`UnitaryKVCacheCoordinator`、`FullAttentionSpec`、无 EAGLE groups、DCP/PCP=1、`prefix_memo_enabled=true`。插桩诊断统计为：8,364 次 `allocate_slots` 失败、8,040 次失败后记录、8,040 次 memo 查询，约 132.4M 个 memoized tokens 返回；并记录 16,404 次 invalidation。高压力 base 校准时 waiting 队列约 26–27，KV 使用率约 99%，观察到自然 preemption。插桩诊断与正式计时分开，不能把诊断吞吐用于 A/B。

## 输出一致性与指标口径

- 五对 A/B 中 prompt token IDs 为 200/200 相同；输出长度、请求状态和 finish reason 均为 200/200 相同。
- 同 seed base-base 控制（pair 5 base 与重复 base）输出 token IDs 为 184/200（92.0%）完全相同；相同 seed 的 pair 5 base-patch 为 186/200（93.0%）。五对 A/B 的精确输出一致率范围为 82.5%–96.0%。这说明本场景的动态批处理/执行差异本身会造成逐 token 波动；仍需对不一致 token 做 logprob 或禁用 prefix caching 的对照，当前没有完成。
- 服务端 `stream_interval=1`，但 SSE 中仍有多 token chunk（单轮最多 14–18 tokens/chunk）。因此脚本报告 `inter_chunk_gap`，并明确 `token_level_itl_valid=false`；没有将该指标误称为 ITL。没有可靠 TPOT 数据。
- JSON 每轮保留 TTFT、E2E 与 chunk-gap 的 p50/p95/p99、请求级 token IDs/指纹和错误。全部正式请求无错误/超时。

## 未完成项目与后续

以下属于预先设计的必测范围，不能由这五对高压力同步数据替代：

1. 高压力 shape 的默认异步调度 A/B，以及至少一个邻近长度/并发配置。
2. 相同负载恢复默认 KV 容量的同步/异步对照。
3. 短/无共享前缀低等待回归的同步/异步对照。
4. 多前缀轮换和自然 eviction/churn 场景的同步/异步对照；需证明 A 请求 memo 复用与失效情况。
5. 上述次要场景需要独立运行配对与足够重复轮次；当前没有统计依据估计它们的退化区间。
6. 针对 A/B 输出差异的禁用 prefix caching 对照、首个分歧 token 的 logprob 检查；以及未插桩性能运行中的 scheduler CPU 时间对照。
7. 代表性更大 dense 模型确认，以及缓存排空/引用生命周期的服务端抽样断言。
